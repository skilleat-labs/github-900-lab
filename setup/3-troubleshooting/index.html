    3. 막혔을 때¶

    실습 중에 자주 나오는 문제와 해결 방법을 모았습니다. 각 실습 페이지의 "막히면"에도 그 실습에 맞는 대처가 있습니다.

    계정과 접속¶

    github.com이 열리지 않거나 아주 느립니다

    회사망 보안 정책 때문일 수 있습니다. 휴대폰 핫스팟으로 연결해 보고, 그래도 안 되면 강사에게 알려 주세요.

    로그인했는데 자꾸 로그아웃됩니다

    브라우저의 시크릿 모드를 쓰고 있거나 쿠키가 차단된 경우입니다. 일반 창에서 로그인합니다.

    초대와 권한¶

    초대를 보냈다는데 받은 게 없습니다
    1. 오른쪽 위 종 모양(알림) 을 확인합니다.
    2. 가입할 때 쓴 메일함을 확인합니다 (스팸함 포함).
    3. 주소로 직접 들어갑니다: https://github.com/<소유자 아이디>/<리포지토리 이름>/invitations
    4. 그래도 없으면 보낸 사람이 Settings → Collaborators에서 내 아이디가 Pending(대기)으로 있는지 확인합니다. 아이디 철자가 틀렸으면 지우고 다시 초대합니다.
    파일 연필 아이콘이 없습니다 (고칠 수 없음)

    그 리포지토리의 협력자가 아니거나 초대를 아직 수락하지 않은 상태입니다. 위 초대 문제를 먼저 해결합니다.

    Settings 탭이 없습니다

    리포지토리 소유자만 Settings를 볼 수 있습니다. 팀 리포지토리에서는 PO에게 부탁합니다.

    웹페이지 (GitHub Pages)¶

    웹페이지 주소가 404 There isn't a GitHub Pages site here 로 나옵니다
    1. Settings → Pages → Build and deployment의 Source가 GitHub Actions인지 확인합니다.
    2. Actions 탭 → 왼쪽 웹페이지 배포 → 오른쪽 Run workflow → Run workflow를 누릅니다.
    3. 초록 체크가 뜰 때까지 1~2분 기다린 뒤 주소를 새로고침합니다.
    4. 주소 끝에 리포지토리 이름이 있는지 확인합니다: https://<아이디>.github.io/lunch-practice/
    Actions 탭에 '웹페이지 배포'가 빨간 X로 실패했습니다

    템플릿으로 리포지토리를 만든 직후에는 Pages가 꺼져 있어서 첫 배포가 실패합니다. 정상입니다. Pages를 켠 뒤 위 방법으로 다시 실행합니다.

    고쳤는데 웹페이지에 반영이 안 됩니다

    배포에 1~2분 걸립니다. Actions 탭에서 웹페이지 배포가 끝났는지 확인하고, 브라우저에서 강력 새로고침(Windows Ctrl + F5, Mac Cmd + Shift + R)을 합니다.

    자동 검사 (메뉴 데이터 검사)¶

    PR에 빨간 X와 '메뉴 데이터 검사' 실패가 보입니다

    Details를 눌러 빨간 글씨를 읽습니다. 대부분 아래 셋 중 하나입니다.

    메시지 원인 해결
    올바른 JSON 형식이 아닙니다 쉼표, 따옴표, 괄호 실수 메뉴 줄 끝 쉼표를 확인합니다. 마지막 메뉴 뒤에는 쉼표가 없어야 하고, 나머지는 모두 있어야 합니다
    price(가격)는 0보다 큰 숫자여야 합니다 가격을 "9000"처럼 따옴표로 감쌈 숫자는 따옴표 없이 9000
    delivery(배달 가능)는 true 또는 false여야 합니다 "yes", "true"처럼 글자로 씀 따옴표 없이 true 또는 false

    파일을 고쳐서 같은 분기에 다시 커밋하면 검사가 자동으로 다시 돕니다.

    분기와 PR¶

    Compare & pull request 노란 배너가 안 보입니다

    배너는 커밋 직후 잠시만 보입니다. Pull requests 탭 → New pull request → compare에서 내 분기를 고르면 됩니다.

    엉뚱한 분기에 커밋했습니다

    커밋할 때 대화상자에서 분기를 확인하지 않으면 main에 바로 커밋될 수 있습니다. 실습에서는 큰 문제가 아닙니다. 다음부터는 화면 왼쪽 위 분기 드롭다운이 내 분기인지 먼저 확인하고 편집합니다.

    Approve(승인)를 고를 수 없습니다

    자기가 만든 PR은 자기가 승인할 수 없습니다. 짝꿍이나 팀원이 승인해야 합니다.

    그래도 안 되면¶

    손을 들거나 강사에게 화면을 보여 주세요. 막힌 화면의 주소(브라우저 주소창)를 같이 알려 주면 빨리 찾을 수 있습니다.
