    확인 퀴즈¶

    4교시는 따라하기 뒤 바로 팀 구성을 하므로 혼자 해보기가 짧습니다. 팀 구성을 기다리는 동안이나 수업이 끝난 뒤 복습으로 풀어 보세요.

    혼자 해보기: 우선순위 보드 만들기¶

    목표

    내 연습 보드에 우선순위 기준으로 칸이 나뉜 보드 뷰를 하나 더 만듭니다. 실습 4-2의 보드는 Status(Todo, In Progress, Done)로 칸이 나뉘었지만, 이번에는 상, 중, 하로 칸을 나눕니다. 오후 팀 실습에서 MoSCoW(Must, Should, Could, Won't)로 보드를 묶을 때와 같은 방법입니다.

    소요 시간 약 5분 실습 장소 개인 프로젝트 내 연습 보드

    완료 조건¶

    • 내 연습 보드에 우선순위 보드라는 이름의 보드 뷰가 있다
    • 보드 칸이 상, 중, 하로 나뉘어 있다
    • 카드 하나를 하 칸에서 상 칸으로 옮기면, 표 뷰에서도 그 이슈의 우선순위가 상으로 바뀐다
    • 뷰 설정이 저장되어 새로고침해도 그대로다
    힌트 1

    새 보드 뷰를 만드는 방법은 실습 4-2 STEP 4와 같습니다. + New view → 검색창 오른쪽 톱니바퀴 View options(뷰 설정) → Layout → Board.

    힌트 2

    보드 칸을 무엇으로 나눌지는 검색창 오른쪽 톱니바퀴 View options(뷰 설정)의 Column by(칸 기준)에서 정합니다. 기본값이 Status입니다.

    힌트 3

    Column by에서 우선순위를 고른 뒤 뷰 이름을 바꾸고 Save를 누릅니다. 보드에서 카드를 다른 칸으로 끌면 그 카드의 우선순위 값이 바뀝니다.

    정답 예시
    1. 내 연습 보드 → 뷰 탭 오른쪽 + New view
    2. 검색창 오른쪽 톱니바퀴 View options(뷰 설정) → Layout → Board
    3. 같은 View options → Column by → 우선순위
    4. 뷰 탭 이름을 더블클릭해 우선순위 보드로 바꾸고 Enter
    5. Save 클릭
    6. 하 칸의 카드 하나를 상 칸으로 끌어 놓기
    7. 첫 번째 표 뷰로 가서 그 이슈가 상 묶음에 있는지 확인

    표, 보드, 로드맵은 같은 데이터이므로 보드에서 칸을 옮기는 것이 곧 필드 값을 바꾸는 것입니다.

    확인 퀴즈¶

    Q1. Projects의 표(Table), 보드(Board), 로드맵(Roadmap)은 무엇이 다른가요?

    정답: 데이터는 같고 보는 모양만 다릅니다.

    • 표: 엑셀처럼 줄과 칸으로 보며 정렬하고 묶을 때 좋습니다.
    • 보드: Todo, In Progress, Done 같은 칸에 카드를 두고 끌어서 옮깁니다. 매일 진행을 볼 때 좋습니다.
    • 로드맵: 스프린트나 날짜 필드를 기준으로 시간축 위에 막대로 그립니다. 일정을 보고할 때 좋습니다.

    한 뷰에서 값을 바꾸면 다른 뷰에도 바로 반영됩니다.

    Q2. MVP는 무엇인가요?

    정답: Minimum Viable Product, 최소 기능 제품입니다. 가치를 확인할 수 있는 가장 작은 출시 범위이며, MoSCoW에서 Must만 모은 것입니다.

    점심 메뉴 서비스라면 "메뉴를 한눈에 보고 예산으로 거를 수 있다"만 되어도 "메뉴 결정 시간 5분 이내"라는 목표를 시험해 볼 수 있습니다.

    Q3. 요청자가 거의 모든 요구를 Must라고 합니다. 어떻게 해야 하나요?

    정답: Must가 많으면 MVP가 아닙니다. 각 요구에 "이것이 없으면 정말 출시를 못 하나?"를 물어 Must를 줄입니다.

    • 없어도 서비스의 핵심 가치(메뉴를 빨리 정하기)를 확인할 수 있다면 Should나 Could입니다.
    • 범위가 크고 이번에 하기 어려운 것(로그인이 필요한 투표 등)은 Won't로 명시합니다. Won't는 "안 한다"가 아니라 "이번에는 안 한다"입니다.
    • 오후 실습에서는 Must를 3개 이하로 제한합니다.
    Q4. PR 본문에 Closes #12라고 쓰면 무슨 일이 일어나나요?

    정답: 12번 이슈와 PR이 연결되고, PR이 병합되는 순간 12번 이슈가 자동으로 닫힙니다.

    Projects의 Item closed 자동화가 켜져 있으면 그 이슈 카드가 보드에서 Done으로 자동 이동합니다. PR 하나 병합으로 이슈 종료와 보드 정리가 함께 일어납니다. Fixes #12, Resolves #12도 같습니다. 그냥 #12만 쓰면 링크만 걸리고 이슈는 닫히지 않습니다.

    Q5. PO와 PM은 무엇이 다른가요?

    정답: PO는 무엇을, 왜 만들지 정하고, PM은 언제, 누가 할지 정합니다.

    PO (제품 책임자) PM (프로젝트 관리자)
    관심 제품의 가치와 범위 일정과 진행
    정하는 것 우선순위, MVP 범위, 충돌 요구 결정, 최종 승인 담당자 배정, 스프린트, 마일스톤, 병합 관리
    오늘 실습 에픽 등록, MoSCoW 지정, 릴리스 발행 라벨, 마일스톤, 팀 보드 관리

    3인 팀은 PO가 PM을 겸합니다.

    남겨 둘 이슈, PR 팀 리포지토리에는 이슈와 PR이 없습니다. 팀 라벨, 마일스톤, 이슈 템플릿도 아직 없습니다 (5교시에 만듭니다). 개인 lunch-practice와 내 연습 보드는 복습용으로 그대로 둡니다
