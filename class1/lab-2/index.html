    실습 1-2. 웹에서 고치고 커밋하기¶

    이번 실습에서 할 것

    • README.md를 웹에서 고치고 커밋합니다.
    • 새 파일 docs/my-note.md를 만들고 커밋합니다.
    • site/menus.json의 김치찌개 가격을 고치고 커밋한 뒤, 웹페이지에 반영되는 것을 확인합니다.

    소요 시간 약 8분 실습 장소 개인 연습 리포지토리 lunch-practice 관련 교안 1교시 교안

    준비¶

    • 실습 1-1을 마쳐서 https://github.com/<내아이디>/lunch-practice가 있고, 웹페이지가 열리는 상태여야 합니다.
    • 리포지토리 첫 화면(Code 탭)을 열어 둡니다. 커밋 수가 1 Commit입니다.
    • 이번 실습이 끝나면 커밋이 3개 늘어 4 Commits가 됩니다.

    STEP 1. README.md 편집 화면 열기¶

    1. 리포지토리 첫 화면의 파일 목록에서 README.md를 클릭합니다.
    2. 파일 내용이 보이는 화면으로 바뀝니다. 내용 위쪽 오른편에 있는 연필 아이콘(마우스를 올리면 Edit this file이라고 나옵니다)을 클릭합니다.
    3. 편집 화면이 열립니다. 위쪽에 lunch-practice / README.md in main이 보이고, 그 아래에 Edit(편집)과 Preview(미리 보기) 탭이 있습니다.

    확인: 편집 칸 안에 지금 README 내용이 줄 번호와 함께 보입니다.

    # 점심 메뉴 추천 서비스

팀원들이 점심 메뉴를 빨리 고를 수 있게 돕는 서비스입니다.

    STEP 2. 내 이름 한 줄 추가하기¶

    1. 편집 칸의 마지막 줄(팀원들이 점심 메뉴를...) 끝을 클릭해 커서를 둡니다.
    2. Enter 를 두 번 눌러 빈 줄을 하나 만들고 그 아래로 내려갑니다.

    3. 아래 내용을 입력합니다. 홍길동은 내 이름으로 바꿉니다.

      ## 만든 사람

- 홍길동

    4. 위쪽 Preview 탭을 클릭해 봅니다. "만든 사람"이 소제목으로, 내 이름이 점 목록으로 보이는지 확인합니다.

    5. 다시 Edit 탭을 클릭합니다. (Preview에서 바로 커밋해도 됩니다.)

    확인: 편집 칸이 아래처럼 되어 있습니다.

    # 점심 메뉴 추천 서비스

팀원들이 점심 메뉴를 빨리 고를 수 있게 돕는 서비스입니다.

## 만든 사람

- 홍길동

    STEP 3. 커밋하기¶

    편집한 내용은 아직 저장되지 않았습니다. 커밋을 해야 저장 기록 한 건으로 남습니다.

    1. 화면 오른쪽 위의 초록색 Commit changes...(변경 저장) 버튼을 클릭합니다.

    2. Commit changes 대화상자가 열립니다. 각 칸을 아래처럼 채웁니다.

      칸 입력할 값 설명
      Commit message (커밋 메시지) README에 만든 사람 추가 기본값 Update README.md를 지우고 씁니다
      Extended description (자세한 설명) 실습 1-2에서 내 이름을 추가함 선택 항목. 이유나 배경을 적습니다
      분기 선택 Commit directly to the main branch 기본으로 선택되어 있습니다. 그대로 둡니다 
      README에 만든 사람 추가

      실습 1-2에서 내 이름을 추가함

    3. 대화상자 아래의 초록색 Commit changes 버튼을 클릭합니다.

    확인: README.md 파일 화면으로 돌아오고, 내용 위 회색 줄에 내 아이디와 README에 만든 사람 추가 메시지, 그리고 now(방금)가 보입니다.

    Create a new branch for this commit and start a pull request는 무엇인가요?

    대화상자 아래쪽에 있는 두 번째 선택지입니다. 원본(main)을 바로 고치지 않고, 사본(분기)에 커밋한 뒤 검토를 요청하는 방식입니다. 혼자 쓰는 연습 리포지토리라 지금은 main에 바로 커밋합니다. 여럿이 쓰는 리포지토리에서는 이 두 번째 방식을 씁니다. 3교시에 직접 해 봅니다.

    좋은 커밋 메시지 예시

    이렇게 쓰지 않습니다 이렇게 씁니다
    Update README.md (기본값 그대로) README에 만든 사람 추가
    수정 회의록 링크 오타 수정
    최종 가격 기준을 만 원으로 변경

    "무엇을, 왜"가 한 줄에 들어가면 좋은 메시지입니다.

    STEP 4. 새 파일 docs/my-note.md 만들기¶

    이번에는 기존 파일을 고치는 대신 새 파일을 만듭니다. docs 폴더 안에 내 메모 파일을 만듭니다.

    1. 위쪽 리포지토리 이름 lunch-practice를 클릭해 첫 화면으로 돌아갑니다.
    2. 파일 목록 위쪽의 Add file(파일 추가) 버튼을 클릭합니다.
    3. 펼쳐진 메뉴에서 Create new file(새 파일 만들기)를 클릭합니다.

    4. 위쪽에 lunch-practice / 다음으로 Name your file... 칸이 있습니다. 이 칸에 아래 이름을 입력합니다.

      docs/my-note.md

      docs/까지 입력하는 순간 슬래시(/)가 폴더 구분으로 바뀌어 lunch-practice / docs / 모양이 되고, 칸에는 my-note.md만 남습니다. GitHub 웹에서는 파일 이름 앞에 폴더/를 붙이는 것으로 폴더 안에 파일을 만듭니다.

    5. 아래 편집 칸에 아래 내용을 붙여 넣습니다.

      # 내 메모

- 오늘 배운 것: 커밋은 저장 기록 한 건이다.
- 커밋 메시지는 무엇을 왜 바꿨는지 쓴다.

    6. 오른쪽 위 Commit changes... 버튼을 클릭합니다.

    7. Commit message 칸의 기본값 Create my-note.md를 지우고 아래처럼 씁니다.

      수업 메모 파일 추가

    8. Commit directly to the main branch가 선택되어 있는지 확인하고, Commit changes를 클릭합니다.

    확인: 리포지토리 첫 화면에서 docs 폴더를 클릭하면 00_현업요청.md, 01_킥오프_회의록.md, 02_현행_업무.md, images 사이에 my-note.md가 보입니다.

    빈 폴더는 만들 수 없나요?

    Git은 파일만 기록합니다. 폴더는 그 안에 파일이 있을 때만 생깁니다. 그래서 GitHub 웹에서 새 폴더를 만들 때는 항상 "폴더 이름/파일 이름"으로 파일을 하나 함께 만듭니다.

    STEP 5. 김치찌개 가격 고치기¶

    이번에는 웹페이지의 메뉴 데이터를 고칩니다. 지금 site/menus.json의 내용은 아래와 같습니다.

    [
  { "name": "김치찌개", "category": "한식", "price": 9000, "distance": 300, "solo": true },
  { "name": "짜장면", "category": "중식", "price": 8000, "distance": 450, "solo": false },
  { "name": "돈카츠", "category": "일식", "price": 11000, "distance": 600, "solo": false },
  { "name": "샐러드볼", "category": "양식", "price": 10500, "distance": 200, "solo": true },
  { "name": "쌀국수", "category": "아시안", "price": 9500, "distance": 700, "solo": false },
  { "name": "순두부찌개", "category": "한식", "price": 8500, "distance": 350, "solo": true }
]

    한 줄이 메뉴 하나입니다. "price": 9000이 가격, "distance": 300이 회사에서의 거리(미터)입니다.

    1. 리포지토리 첫 화면에서 site 폴더를 클릭합니다.
    2. menus.json을 클릭합니다.
    3. 오른쪽 위 연필 아이콘(Edit this file)을 클릭합니다.

    4. 2번째 줄, 김치찌개 줄에서 9000만 찾아 9500으로 바꿉니다. 숫자만 바꾸고 쉼표, 따옴표, 중괄호는 건드리지 않습니다.

      고치기 전:

        { "name": "김치찌개", "category": "한식", "price": 9000, "distance": 300, "solo": true },

      고친 뒤:

        { "name": "김치찌개", "category": "한식", "price": 9500, "distance": 300, "solo": true },

    5. 오른쪽 위 Commit changes... 버튼을 클릭합니다.

    6. Commit message 칸의 기본값 Update menus.json을 지우고 아래처럼 씁니다.

      김치찌개 가격 9500원으로 수정

    7. Extended description 칸에는 이유를 적어 봅니다.

      식당 가격 인상 반영

    8. Commit directly to the main branch가 선택되어 있는지 확인하고, Commit changes를 클릭합니다.

    확인: menus.json 화면에서 김치찌개 줄이 "price": 9500으로 보이고, 위쪽 회색 줄에 김치찌개 가격 9500원으로 수정이 보입니다.

    쉼표 하나가 웹페이지 전체를 멈춥니다

    menus.json은 JSON이라는 엄격한 형식입니다. 메뉴 줄 끝의 쉼표를 지우거나, 따옴표를 하나 빠뜨리면 웹페이지가 메뉴를 하나도 읽지 못합니다. 숫자만 바꾸세요.

    STEP 6. 웹페이지에 반영된 것 확인하기¶

    main에 커밋이 생기면 웹페이지 배포 작업이 자동으로 다시 돕니다. 실습 1-1처럼 Run workflow를 누를 필요가 없습니다.

    1. 리포지토리 위쪽 탭에서 Actions를 클릭합니다.
    2. 목록 맨 위에 김치찌개 가격 9500원으로 수정이라는 실행 기록이 노란 원(실행 중)으로 보입니다. 그 아래에는 방금 한 다른 두 커밋의 실행 기록도 보입니다.
    3. 1~2분 기다려 맨 위 기록이 초록 체크로 바뀌는 것을 확인합니다.
    4. 실습 1-1에서 열어 둔 웹페이지 탭(https://<내아이디>.github.io/lunch-practice/)으로 가서 새로고침합니다.

    확인: 김치찌개 카드의 가격이 9,500원으로 바뀌어 있습니다.

    커밋 하나가 웹페이지까지 가는 길

    flowchart LR
    A["웹에서 menus.json 수정"] --> B["Commit changes<br/>(main에 커밋)"]
    B --> C["웹페이지 배포 작업<br/>자동 실행"]
    C --> D["웹페이지에<br/>9,500원 표시"]
    이렇게 커밋을 계기로 자동 작업이 도는 기능을 GitHub Actions라고 합니다. 6교시에 자세히 봅니다.

    성공하면¶

    • README.md에 ## 만든 사람과 내 이름이 있습니다.
    • docs/my-note.md 파일이 있습니다.
    • site/menus.json의 김치찌개 가격이 9500입니다.
    • 리포지토리 첫 화면의 커밋 수가 4 Commits입니다.
    • 웹페이지에서 김치찌개가 9,500원으로 보입니다.

    막히면¶

    연필 아이콘이 안 보입니다

    폴더 목록 화면에 있는 경우입니다. 파일 이름(README.md, menus.json)을 클릭해 파일 내용이 보이는 화면으로 들어가야 연필 아이콘이 보입니다. 또는 Starter(skilleat-labs/lunch-picker-starter) 화면에 있으면 편집 권한이 없어 "Fork this repository" 안내가 나옵니다. 주소창이 내 lunch-practice인지 확인합니다.

    Commit changes 대화상자에 Commit directly to the main branch가 없습니다

    내 리포지토리가 아닌 곳에서 편집하는 경우입니다. 주소창을 확인해 내 lunch-practice로 이동한 뒤 다시 편집합니다.

    docs/my-note.md가 docs 폴더가 아니라 맨 위에 docs-my-note.md 같은 이름으로 생겼습니다

    이름 칸에 슬래시 대신 다른 문자를 입력한 경우입니다. 그 파일을 열고 연필 아이콘을 눌러 편집 화면에서 이름 칸을 docs/my-note.md로 고친 뒤 다시 커밋하면 파일이 옮겨집니다.

    웹페이지에 메뉴가 하나도 안 보입니다

    menus.json을 고치다가 쉼표, 따옴표, 중괄호를 건드린 경우입니다. menus.json을 열고 김치찌개 줄이 위 "고친 뒤" 코드와 글자 하나까지 같은지 비교해 고친 뒤 다시 커밋합니다.

    Actions는 초록 체크인데 웹페이지 가격이 그대로입니다

    브라우저가 예전 화면을 기억하고 있는 경우입니다. 강력 새로고침(Windows Ctrl+Shift+R, Mac Cmd+Shift+R)을 합니다. 그래도 그대로면 1분 정도 더 기다립니다.
